# ADR-0006: необязательный Chipoint и объединение в пределах кадра

Дата: 2026-09-30. Статус: принято.

## Контекст

`idea2.md` предлагает независимых экспертов, сохранение координат retrieval и late fusion.
Пользователь хочет работать с imajev даже при медленном или отключённом Chipoint.
Полный reranker Chipoint невоспроизводим по опубликованному контракту; официальный demo
также оставляет его отключённым. Нельзя обещать accuracy полного benchmark pipeline.

## Решение

- Отдельный локальный процесс Chipoint с установщиком и весами внутри репозитория.
  По умолчанию один SigLIP2 tower, street gallery и projection head; второй tower опционален.
- Захват и novelty общие. Основной worker сразу запускает imajev. Через Qt-сигнал запускается
  максимум один дополнительный HTTP worker; ответ imajev публикуется без ожидания Chipoint.
- GeoExpert возвращает единый GeoEvidence. Геометрическое сопоставление координат и
  softmax retrieval scores живут в infrastructure, правила fusion — в domain.
- `fuse_evidence`: линейная смесь в пределах одного кадра (65/35, с unknown). Это исходная
  экспериментальная настройка, не обученные веса. Перемножение некалиброванных экспертов
  не применяется, чтобы снова не усиливать ложную уверенность.
- `Session.supplement` пересобирает раунд в исходном порядке кадров с прежними novelty.
  Поздний ответ уточняет старый кадр, не увеличивает счётчик и не подменяет последний кадр.
- SQLite получает новую таблицу `supplementary_observations`. Сырые ответы imajev остаются
  неизменными, Chipoint сохраняет все координаты и scores. Snapshot публикуется после транзакции.
- Отключение Chipoint помечает его сохранённые вклады неактивными и пересчитывает текущий
  раунд только по imajev. Номер раунда, основные ответы и число кадров сохраняются.
- Round ID и поколение включения защищают от ответов после сброса/отключения.
  Уже запущенный серверный запрос может завершиться; новые кадры к нему не выстраиваются в очередь.

## Последствия

Можно сравнивать imajev и fusion на одних сохранённых ответах:
`scripts/replay_rounds.py --imajev-only`. По умолчанию replay учитывает активные дополнения.
Откат функциональности — выключить Chipoint; миграция БД только добавляет таблицу.
Уточнение от 2026-09-30: после Chipoint imajev дополнительно проверяет недостающие
региональные ветви. Эти ответы дописываются к исходному raw JSON imajev и сохраняются
при отключении Chipoint. Незавершённый ответ при отключении игнорируется. Формула
регионального объединения `linear_experts_v2` и мягкие признаки описаны в ARCHITECTURE.md.
На длинных раундах пересборка стоит O(кадры × географические классы); изображения в истории
Session не удерживаются. Для очень длинных сессий понадобится инкрементальный аккумулятор.

Общий GPU всё ещё делится между процессами: отсутствие ожидания в UI не означает нулевого
влияния Chipoint на задержку imajev. При необходимости запускается только imajev.
Измеренная точность, learned fusion, H3/S2, пространственное сглаживание и семантическая
новизна остаются отдельными этапами. См. [сервис](../../services/chipoint/README.md).
