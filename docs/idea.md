Да. На **RTX 3090 Ti 24 ГБ** я бы строил систему так, чтобы обычный запрос укладывался существенно быстрее 1 секунды, а **1–2 секунды были верхним бюджетом для сложного случая с дополнительным Visual-Jev-проходом**.

Ключевой вывод: **не стоит заставлять одну VLM последовательно три раза угадывать континент → страну → регион**. Для геолокации уже есть специализированные модели, которые делают это лучше и быстрее.

## Что я бы взял за основу

Если задача именно:

> фотография → континент → страна → регион → возможно координаты,

то мой выбор сейчас — **Chipoint v2 как готовая основа + архитектурные идеи HierLoc**.

Не `imajev`.

`imajev-4b` я бы добавил **вторым модулем**, когда основная географическая модель не уверена.

Почему: Chipoint v2 специально обучен на геолокации и уже имеет открытые веса. На OSV-5M авторы приводят для street-view ветви:

| Радиус от истинного места | Chipoint v2 |
|---:|---:|
| ≤25 км | **44,8%** |
| ≤200 км | **81,1%** |
| ≤750 км | **92,1%** |
| ≤2500 км | **96,8%** |
| медианная ошибка | **32 км** |

Это self-reported результаты авторов, поэтому я бы обязательно перепроверил их на своём тестовом наборе. Но как готовая отправная точка модель выглядит сейчас существенно интереснее GeoCLIP. :chatgpt-content-reference{index="0"}

Для Chipoint v1 авторы также рассчитали приблизительную административную точность: **~85,6% страна и ~61,7% admin-1/регион**. Для сравнения, HierLoc сообщает 82,9% для страны, 55,0% для региона, 40,7% для subregion и 23,3% для города на OSV5M. :chatgpt-content-reference{index="1"}

И самое интересное: **HierLoc практически буквально реализует вашу первоначальную идею**:

```text
                         ФОТОГРАФИЯ
                              │
                              ▼
                         DINOv3 encoder
                              │
                        image embedding
                              │
                              ▼
                    Country candidates
                       ↓       ↓       ↓
                    Germany  Austria  Czechia
                       │
                       ▼
                    Region
                 Hessen / Bayern / ...
                       │
                       ▼
                  Sub-region
                       │
                       ▼
                     City
```

Только вместо независимых классификаторов там географические сущности расположены в общем иерархическом embedding-пространстве и используется beam search. Это намного правильнее жёсткой последовательности из трёх отдельных классификаторов. :chatgpt-content-reference{index="2"}

# Что будет с быстродействием на вашей 3090 Ti

У вас очень подходящая карта для этой задачи: **24 ГБ VRAM**, 10 752 CUDA-ядер и 384-битная GDDR6X. :chatgpt-content-reference{index="3"}

Я бы ориентировался на такой бюджет, но подчёркиваю: значения для 3090 Ti ниже — **инженерная оценка**, пока мы не запустили конкретные модели на вашей машине.

| Этап | Ожидаемый порядок времени |
|---|---:|
| decode/resize изображения | 5–30 мс |
| DINO/географический encoder | ~30–150 мс |
| поиск кандидатов | единицы–десятки мс |
| country/region hierarchy | единицы–десятки мс |
| reranker | ~20–150 мс |
| **чистая специализированная геолокация** | **~0,1–0,5 с** |
| + imajev-4B для сложного случая | **~0,4–1,5 с дополнительно** |
| **весь сложный запрос** | ориентир **~0,7–2 с** |

Причём сама HierLoc в своей реализации сообщает всего **2,16 мс для model inference + retrieval на использованном ими GPU** после получения нужных данных; напрямую переносить эту цифру на вашу карту нельзя, но она хорошо показывает, что hierarchical search — совсем не узкое место. :chatgpt-content-reference{index="4"}

Главный расход времени — **извлечение image embedding**, а не проход country → region → city.

# Где здесь нужен imajev-4b

Вот здесь система становится особенно интересной.

Я бы сделал не:

```text
photo
 ↓

 ↓
imajev: country
 ↓

```

а:

```text
                        PHOTO
                          │
                          ▼
                   GEO ENCODER
                  DINOv3 / Chipoint
                          │
             ┌────────────┴────────────┐
             │                         │
             ▼                         ▼
       geographic tree            image embedding
             │
             ▼
       top candidates
             │
 Germany 0.42
 Austria 0.31
 Czechia 0.11
 Slovenia 0.07
             │
             ▼
     confidence sufficient?
        │            │
       YES           NO
        │            │
        │            ▼
        │       imajev-4b
        │
        │      «Germany, Austria,
        │       Czechia or Slovenia?»
        │
        │      «Alpine landscape?»
        │      «German road markings?»
        │      «Austrian bollards?»
        │      «Which architecture

        │            │
        └──────┬─────┘
               ▼
        probability fusion
               │
               ▼
 Country → Region → Subregion
          + coordinates
          + uncertainty
```

То есть **Visual-Jev выступает reranker/judge**, а не основным геолокатором.

Это даст и скорость, и возможность добавлять совершенно новые признаки без переобучения основной модели.

# А imajev-4b потянет 3090 Ti?

Да, причём с большим запасом по памяти.

У `imajev-4b`:

- Qwen3.5-4B;
- базовые веса около **9,3 ГБ**;
- LoRA + decision head — ещё примерно **122 МБ**;
- vision tower остаётся frozen;
- вместо генерации предложения используется direct readout logits;
- есть специальный вариант `unknown`. :chatgpt-content-reference{index="5"}

На H100 авторы получили для изображения примерно **91 мс** с `--fast --merge-lora`, а штатный режим с четырьмя перестановками вариантов — около **350 мс**. :chatgpt-content-reference{index="6"}

H100 существенно быстрее вашей Ampere, поэтому переносить 91 мс нельзя. У H100 гораздо выше Tensor throughput и около 3,35 ТБ/с пропускной способности памяти против примерно 1 ТБ/с у 3090 Ti. :chatgpt-content-reference{index="7"}

Поэтому для 3090 Ti я бы предварительно закладывал примерно:

**imajev-4b / один visual decision: ~0,3–0,8 с.**

И это выглядит вполне реалистичным для вашего требования.

Четыре rotation, которые использует автор для повышения устойчивости к порядку ответов, могут уже подвести вас к **1–2 секундам**.

Поэтому в вашем приложении я бы начинал с:

```text
rotations = 1
```

и калибровал модель на собственном датасете.

Если окажется, что смена порядка вариантов заметно влияет на результат — попробовать `rotations=2`.

# 9B я бы на 3090 Ti не выбирал

У `imajev-9b` только веса занимают около **19,3 ГБ**. :chatgpt-content-reference{index="8"}

У вас 24 ГБ.

Формально загрузить можно, но нужны ещё:

```text
model weights
+ vision tensors
+ activations
+ KV/recurrent cache
+ CUDA workspace
+ PyTorch allocator
+ image buffers
```

То есть вы окажетесь около предела VRAM.

И главное — на собственном benchmark авторов **4B оказался даже немного лучше 9B**:

```text

imajev-4b   83.9%
imajev-9b   82.1%
```

Это не геолокационный benchmark, а ImajevBench, поэтому нельзя переносить эти 83,9% на вашу задачу. Но оснований брать 9B ради качества здесь нет. :chatgpt-content-reference{index="9"}

**4B — очевидная sweet spot для вашей 3090 Ti.**

# Нужно ли поднимать её через LM Studio?

**Нет. Я бы специально не использовал LM Studio для этой модели.**

LM Studio великолепно подходит для обычных LLM/VLM:

```text
Qwen
Llama
Gemma
...
```

Он умеет загружать модели, держать их в памяти и предоставлять локальный REST/OpenAI-compatible API. Он также умеет передавать изображения VLM. :chatgpt-content-reference{index="10"}

Но `imajev` — это не просто:

> Qwen3.5-4B + необычный prompt.

Там имеется:

```text
Qwen3.5-4B
    │
    ├── frozen vision encoder
    │
    ├── LoRA adapter
    │
    └── custom 255-code decision readout
             │
             ▼
           logits
             │
          softmax
             │
    option probabilities
```

То есть нужен **собственный inference-код**.

LM Studio стандартно ожидает обычный inference/generation pipeline. Даже если слить LoRA в Qwen, остаётся custom decision readout и специальная логика получения probability.

Поэтому я бы запускал imajev **отдельно**.

# Как модель должна жить в вашем приложении

Не надо загружать веса при каждой фотографии.

Нормальная архитектура:

```text
Windows
│
├── ваше GUI-приложение
│
│       HTTP / localhost
│       ↓
│
└── inference-service
        │
        ├── Chipoint / DINOv3
        │      GPU resident
        │
        ├── FAISS/entity index
        │      RAM / VRAM
        │
        └── imajev-4b
               GPU resident
```

При запуске inference server:

```text
1. загрузить веса
2. отправить их в RTX 3090 Ti
3. прогреть CUDA kernels
4. держать модель в VRAM
5. ждать запросы
```

На каждую фотографию приложение отправляет только:

```text
image
+ параметры
```

и получает:

```json
{
  "continent": {
    "Europe": 0.987
  },
  "country": {
    "Germany": 0.61,
    "Austria": 0.22,
    "Czechia": 0.07
  },
  "region": {
    "Hessen": 0.34,
    "Bayern": 0.19,
    "Rheinland-Pfalz": 0.13
  },
  "coordinates": {
    "lat": 50.1,
    "lon": 8.7
  },
  "uncertainty_km": 82
}
```

Иными словами, это обычный **локальный microservice**, а не LM Studio.

`imajev` уже поставляется с локальным HTTP server и CUDA/PyTorch backend, поэтому даже API самим с нуля писать не обязательно. :chatgpt-content-reference{index="11"}

## И я бы немного изменил сам принцип трёх классификаций

Не надо вычислять:

\[
\text{континент winner}
\rightarrow
\text{страна winner}
\rightarrow
\text{регион winner}.
\]

Потому что одна ошибка наверху убивает всё дерево.

Например:

```text
Europe       0.94

Germany      0.43
Austria      0.32
Switzerland  0.12
Slovenia     0.06
```

Нужно провести дальше несколько ветвей:

```text
Germany
   ├ Hessen
   ├ Bayern
   └ Baden-Württemberg

Austria
   ├ Tirol
   ├ Salzburg
   └ Vorarlberg

Switzerland
   ├ Zürich
   └ Bern
```

и только потом сравнивать итоговые scores.

Именно поэтому **HierLoc с beam search концептуально лучше трёх независимых классификаторов**. :chatgpt-content-reference{index="17"}

### Поэтому мой выбор для вашего компьютера

**База приложения — Chipoint v2.** Он уже открыт, имеет веса и готовый локальный запуск.

**Архитектуру классификации — взять из HierLoc:** `country → region → subregion → city`, top-k/beam search вместо жёсткого каскада.

**imajev-4b — второй GPU-модуль для неоднозначных случаев**, semantic reranking и произвольных вопросов к фотографии.

**Не LM Studio.** Отдельный CUDA/PyTorch inference service, который постоянно держит модели в памяти.

На вашей **3090 Ti 24 GB** я бы проектировал систему под **<0,5 с fast path** и **до 1–2 с с подключением imajev-4b**. И это, на мой взгляд, намного перспективнее, чем пытаться решить всю геолокацию одной 4B VLM.
