# Архитектура StreetJev

## Системный контекст

```text
Windows: область / окно / файл
            |
            v
Capture adapter -> Frame -> imajev worker ------> GeoEvidence
                      |                               |
                      +--> Chipoint (опционально) ----> Session
                               HTTP worker             |
                                            fusion одного кадра
                                       |
                                GeoRound (DDD)
                                       |
                         SQLite <--- Snapshot ---> Qt Map
```

Приложение — модульный монолит. Контексты «Наблюдение», «Географическое предположение»
и «Отображение» разделены границами пакетов; отдельной сети между ними нет.
Процессы imajev и Chipoint — инфраструктурные зависимости, которыми управляет тот же репозиторий.

## Препроект и критический разбор

Новый персональный Windows desktop инструмент. Частые сценарии: выбрать источник,
сделать кадр, увидеть несколько гипотез, накопить сведения и сбросить раунд.
Подтверждены сменные модели, сохранение evidence, несколько ветвей страны и независимое
накопление во времени. Полная пространственная сетка отложена: первый эксперт выдаёт
административные классы, поэтому клетки сейчас добавили бы ложную детализацию.
Открытые вопросы следующих этапов: калибровочный набор, покрытие Street View,
политика перемещения между соседними регионами, допустимая задержка на целевой GPU.

## Компоненты

| Контекст / модуль | Ответственность | Публичный интерфейс |
|---|---|---|
| Наблюдение | Захват и подготовка изображения | `Frame`, `FrameCapture` |
| География | Каталог кодов стран и регионов | `GeoCatalog`, `Place` |
| Предположение | Наблюдение модели и агрегат раунда | `GeoEvidence`, `Distribution`, `GeoRound` |
| Сценарии | Сброс, приём ответа, атомарное сохранение | `Session`, `AnalysisResult` |
| Inference | Перевод внешнего API в язык предметной области | `GeoExpert`, `ImajevExpert`, `ChipointExpert` |
| Объединение | Согласование экспертов одного кадра | `fuse_evidence`, `Session.supplement` |
| Хранилище | Журнал ответов и снимок состояния | `RoundRepository`, `SqliteRoundRepository` |
| Представление | Карта, действия, статусы | `MainWindow`, `MapView` |

Зависимости направлены к домену. `bootstrap.py` и настройка workers в presentation связывают
адаптеры с портами; domain/application не импортируют Qt, HTTP или CUDA.
Модели никогда не изменяют UI или состояние раунда напрямую.

## Data flow

1. Кнопка, горячая клавиша или таймер запускает один `AnalysisWorker` с текущим round ID.
2. Захват возвращает JPEG (до 1280 px по длинной стороне) и миниатюру 32 × 32.
3. Сравнение миниатюр определяет novelty; почти повторный кадр не отправляется модели.
4. imajev отвечает по всем 240 странам. Для нескольких кандидатов делаются условные
   региональные вопросы; при высоком unknown региональный проход пропускается.
5. Anti-corruption layer проверяет полный набор кодов, числа и формат ответа.
6. `Session` отвергает ответ старого раунда. Домен строит новое состояние без изменения старого.
7. SQLite атомарно сохраняет raw evidence и snapshot. Только после успеха публикуется состояние.
8. UI обновляет полигональную карту и список гипотез. Снимок экрана остаётся только в памяти.
9. Если включён Chipoint и его канал свободен, тот же подготовленный кадр параллельно
   отправляется локальному retrieval-сервису. Основной ответ не ждёт дополнительного.
10. Координаты top-64 локально сопоставляются с Natural Earth. `Session.supplement` заменяет
    evidence соответствующего кадра линейной смесью и пересобирает раунд с исходными весами.
    Повторного учёта кадра нет; raw responses сохраняются раздельно. Подробнее —
    [ADR-0006](adr/0006-optional-chipoint.md).

## Ключевые интерфейсы

Порты определены через `typing.Protocol` в `application/ports.py`:

```python
class GeoExpert(Protocol):
    def infer(self, frame: Frame) -> GeoEvidence: ...

class RoundRepository(Protocol):
    def start(self, snapshot: RoundSnapshot) -> None: ...
    def append(self, snapshot, frame, evidence, novelty) -> None: ...
    def supplement(self, snapshot, frame, evidence, weight) -> None: ...
    def disable_supplements(self, snapshot) -> None: ...
```

Для нового эксперта достаточно реализовать `infer`. Его сырые similarity/logits нельзя
передавать как probabilities: адаптер обязан преобразовать их в сопоставимый формат.
Chipoint сохраняет пространственные кандидаты в raw JSON; текущий адаптер агрегирует их
по административным полигонам. Непрерывное поле и калибратор ещё не реализованы.

## Инварианты и накопление

`GeoRound` — aggregate root. `Frame`, `GeoEvidence`, `Distribution`, `Place` — объекты-значения.
Результат модели неизменяем; накопленное состояние принадлежит одному раунду.

```text
weight_t = novelty_t × (1 − unknown_t)
score_t(c) = Σ weight_i × P_i(c) / Σ weight_i
```

Используется линейное объединение распределений (`weighted_linear_v2`). Оно не требует
считать кадры независимыми свидетельствами и не возводит повторяющуюся оценку в степень.
Результат — выпуклая комбинация: оценка страны не превышает максимум её оценок на учтённых кадрах.
При нулевом общем весе остаётся равномерное распределение, которое UI показывает как отсутствие данных.
Unknown уменьшает вес, полностью неизвестный кадр не меняет накопленные оценки.

Это мера поддержки гипотезы ответами модели, а не калиброванная вероятность правильного ответа.
Совпадения лидеров учитываются только как диагностика согласия. На одинаково ошибочных кадрах
средняя оценка тоже будет ошибочной. Веса яркостной новизны остаются эвристикой.
Старые snapshots не переписываются; новая версия алгоритма записывается в каждом новом snapshot.

Региональные распределения также усредняются, условны и отдельно нормализованы внутри страны. Их вес
дополнительно умножается на вероятность страны в текущем наблюдении. UI использует
совместную массу; сумма регионов страны равна её массе. Неисследованные регионы на карту
не выводятся. `unknown` не интерпретируется как место на карте.

Snapshot содержит отдельно последнее наблюдение, его региональные ветви и unknown. Значения
предыдущих региональных запросов не выдаются за последний кадр. Подробнее о смене формулы:
[ADR-0005](adr/0005-confidence-and-map-scale.md).

Повторный frame ID, повторная миниатюра и неверный round ID не меняют агрегат.
Ошибка входных данных не допускает частичного обновления. Ошибка БД не публикует несохранённое состояние.

## Технологические решения

| Решение | Выбор | Обоснование |
|---|---|---|
| Desktop | Python 3.12 + PySide6 | Уже выбран Python; нативные окна, фоновые задачи |
| Карта | QGraphicsView + Natural Earth | Автономная работа, без браузера и тайлов |
| Модель | Официальный imajev API | Поддержка decision readout и unknown |
| Хранение | SQLite WAL | Локальная транзакция без отдельного сервера БД |
| Конкурентность | Один основной + один необязательный worker, UI-поток | Каждый канал без очереди, imajev не ждёт Chipoint |
| Chipoint | Отдельный процесс, один SigLIP2 tower по умолчанию | Включается независимо, галерея читается блоками |
| Захват | mss / Pillow PrintWindow | Область в физических пикселях, отдельное окно |

## Режимы отказа

| Сбой | Влияние | Обработка |
|---|---|---|
| Сервис не запущен / timeout | Нет нового evidence | Сообщение, остановка автозахвата |
| Chipoint не отвечает / занят / timeout | Нет дополнительного evidence | imajev продолжается, короткий статус и подробная подсказка |
| Закрытое / свёрнутое окно | Нет кадра | Повторный выбор источника |
| Чёрный результат PrintWindow | Нет пригодного кадра | Предложение выбрать область |
| Занята горячая клавиша | Нет глобального действия | Явный статус, кнопки доступны |
| Ошибка ответа / коды / NaN | Evidence отвергнуто | Состояние не меняется |
| Сброс во время inference | Ответ устарел | Проверка round ID перед приёмом |
| SQLite read-only / полный диск | Сохранение не состоялось | Старое состояние сохраняется |
